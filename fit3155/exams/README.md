# Sample exams

ORIGINAL_SAMPLE_EXAM.pdf is a real one given by the FIT3155 teaching team, the other PDF's here are ones generated by coding agents by using a few real methods.

## Coding agent rules for generating sample exams

- Use ORIGINAL_SAMPLE_EXAM.pdf as a base reference.
- Use the teaching material in the notesXX.pdf to understand what is taught.
- Use labXX.pdf questions to understand what type of questions matter and could be assessed in the exam.
- Use LaTeX to create the generated paper modelling it after the ORIGINAL_SAMPLE_EXAM.pdf, the exam paper must be created in a subdirectory within this directory with the name XX/GENERATED_EXAM_XX.pdf where XX is an incremental number.

## Examinable scope

- Examinable weeks are wk01-wk11 only.
- Week 12 (approximation algorithms: vertex cover, metric TSP, knapsack PTAS) is NOT examinable. Do not generate questions on it.

## The observed structure of the exam

- The paper is 60 marks total.
- It has 10 questions, usually 6 marks each.
- Each question gets its own page, followed by a blank working page.
- The question order roughly follows the teaching order of the unit.
- The sample gives broad coverage rather than deep coverage of one area.
- Expect about 1 question per major topic block, sometimes 1-2 questions for closely related weekly topics.
- The original sample covers:
    - Z-algorithm / string preprocessing.
    - Boyer-Moore exact pattern matching.
    - BWT preprocessing / searching / inversion ideas.
    - Ukkonen suffix tree construction reasoning.
    - Compression: Elias-Omega and LZ77.
    - Number-theoretic algorithms: especially Miller-Rabin.
    - Fibonacci heap operations.
    - Amortized analysis.
    - B-trees.
    - Linear programming / simplex.
- Questions are usually conceptual-algorithmic, not coding-heavy.
- Common question styles:
    - Write pseudocode for an efficient algorithm or data-structure operation.
    - Prove a shift, rule, or algorithmic step is safe/correct.
    - Work through a small hand calculation.
    - Decode/encode a small example.
    - Derive a time/space bound.
    - Solve a small simplex tableau problem.
- String questions usually use 1-based indexing and explicitly state assumptions.
- If a complex subroutine is not the focus, the question may give it as built-in, e.g. `zalg`.
- Multi-part questions still total 6 marks, commonly split like 3+3.
- The wording asks for clear justification, but not long essays.
- Good generated exams should reuse the same structure, but ask different problems from the original sample.
