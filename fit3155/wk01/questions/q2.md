# Question 2: Naive Z-value computation

What would be the worst case time-complexity for naively computing the Z-values for a string S[1 .. n]?

## Answer

Instead of using the techniuqes (case 2a, 2b, & 2c) of the Z algorithm which save time making it O(n) = O(n).

We would have to do naive comparisons for each substring for all i in the string.

To achieve the worst-case time complexity for **naively** computing the Z-values, we drop the case 2 optimisations and the left and right pointers relying solely on case 1, naive comparisons.

When comparing naively, we have the outer iteration k that indexes where we are in S when comparing with the prefix using the inner iteration i (S[i] == S[k + i]).

Let k be the iterator that indexes our current position in S[2..n]

Let i be the iterator that indexes our current position within the prefix S[1..i]

When comparing naively we keep compare compare S[i] and S[k+i] for equivalence, when a mismatch occurs we set Z[k] = i

In the worst case for an S with only repeating characters, the comparison loop runs until i reaches i - k + 1 (we run out of string).

But k ranges from [2..n], which means that in this worst case i will reach n - k + 1.

= sum (from k=2..n) of n - k + 1  
= (n-1) + (n-2) + ... 1  
= n(n-1) / 2  
= O(n^2)

Therefore the worst case time complexity is O(n^2).
