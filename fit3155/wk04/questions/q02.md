# Question

Prove that the space-efficient edge representation of suffix trees requires O(n) space. You may assume the size of the alphabet under consideration is fixed.

# Answer

Let n be the length of the string S that the suffix tree is built on.

There are n suffixes in total.

In a suffix tree there are (1) exactly n leaves, and (2) all internal nodes have at least two children, which means at most n - 1 internal nodes.

This means that the maximum number of total nodes is 2n-1 = O(n). And there are (2n-1)-1 edges = O(n).

By using a start and end pointer on each edge, this means that we don't have to explicity store characters but instead a starting index and a end index for where the suffix appears in the original string S saving space and allowing for constant time access.

There are O(n) edges, and each edge stores a constant size (start, end) tuple, the total cost for all edges is O(1 * n) = O(n).

Each internal node stores at most one constant size child pointer per character in the alphabet. Since the alphabet is fixed, the total cost for all nodes is O(1 * n) = O(n).

Compared to the naive version which stores strings as edge labels which in the worst case can be O(n) in size per edge label, which in total is quadratic for all edges, O(n * n) = O(n^2).

Therefore the total space complexity of a suffix tree that uses the space-efficient representation is O(n).
